# Nornium 私服：export 指令 + allweapons 专武发放 + Web 存档编辑器

## 背景结论（已验证）
- 「角色→专武」唯一官方数据映射是 `d_character.firstWeapon`（1★ 白板）；6★ 专武（如 4072601 梦魇之灯）无数据字段关联角色。
- **按你的选择**：专武口径 = 每个角色一把与其武器类型（`d_character.profession` == `d_bag_item_weapon.subType`）匹配的**最高稀有度**武器（并列取 id 最大者）；发放目标 = 仅 xundei（账号 10）；`allweapons` 不带参数默认也只发 xundei（带参数可指定账号 ID/名称或 `all`）。
- 在线会话通过 `handlers/login.js` 已导出的 `onlineAccounts` Map（account_id → session）可寻址，编辑器可做到「在线即改即生效」。

## 一、`export` 控制台指令
文件：`server/src/console.js`、`server/src/store.js`

1. `store.js` 新增：
   - `exportData(destDir)`：把 data 目录（accounts.json + players/）递归拷贝到目标目录；目标不存在则创建；返回 `{ accounts, players, dir }`。
   - `listBackups()`：扫描 data 同级的 `data_*_<stamp>` 快照目录，返回名称与 mtime 列表（给前端用）。
2. `console.js` 新增 `export [目标目录]`（走 `runGated` 维护窗口，保证快照一致性，与 restore/load 同模式）：
   - 带参数：校验路径（复用 `checkLoadSource` 风格的预校验，拒绝等于 data 目录本身）→ `exportData`。
   - 无参数：`store.snapshotData('export')` 落到默认备份位置 `server/data_export_<时间戳>`。
   - 回复 `>>` 风格摘要（账号数/玩家数/目标路径）；`help` 补条目。

## 二、专武发放 + `allweapons` 指令
文件：`server/src/game/arsenal.js`（新）、`server/src/console.js`

1. 新模块 `game/arsenal.js`：
   - `bestWeaponForCharacter(charId)`：按 `profession == subType` 过滤 `d_bag_item_weapon`，rarity 降序、id 降序取第一。
   - `grantCharacterWeapons(player, { charIds })`：对每个可玩角色（复用 `player_new.isPlayableCharacter`，10 个）用 `items.grantItems` 入包一把独立实例（自动分配 uuid、带 weapon_info），返回发放清单。幂等性不做去重（一人一把、重复发放会再给一把）。
2. `allweapons [账号ID|账号名|all]`：不带参数 = xundei（账号 10，代码里命名常量并注释说明）；走 `runGated` → 逐个 `loadPlayer` → 发放 → `savePlayer` → 回复每档发放清单。
3. **一次性发放**：实现完成后对 xundei 执行一次（探测 8101 端口：服务端未运行则跑一次性脚本直接写档；在运行则改走编辑器 HTTP API，见下）。

## 三、Web 存档编辑器（重点）

### 架构（零新依赖，沿用现有技术栈）
- `server/src/httpgate.js`：路由表最前面加 `/editor` 前缀分支 → 委托给新模块 `editorapi.js`；`createGate(port, host, hooks)` 增加可选 hooks 参数（`index.js` 传入 `{ maintenance: withMaintenance }`），export API 需要维护窗口。**现有游戏客户端路由与默认兜底完全不动**。
- `server/src/editorapi.js`（新）：
  - 静态文件：`GET /editor` → `server/editor/` 目录（html/css/js，MIME 白名单，防路径穿越）。
  - JSON API（`{code:0,data}` 信封）：
    - `GET /editor/api/accounts`：账号列表 + 每档摘要（昵称、角色数、货币快照、文件 mtime）
    - `GET /editor/api/player/:id`：整档（player/bag/characters/gacha/mall/plot 只读摘要…）
    - `POST /editor/api/player/:id/update`：应用编辑操作数组（见下）
    - `GET /editor/api/catalog`：道具/武器/角色目录（名称查 `d_word_cn`），供前端选择器
    - `POST /editor/api/export`：`{path?}` 走维护窗口导出；`GET /editor/api/backups`：快照列表
  - **在线感知写档**：`onlineAccounts` 里有该账号 → 直接改 `session.player` + `savePlayer` + 推送 `ntf_item_info` / `ntf_character_info`（改动秒生效，游戏内不用重登）；离线 → `loadPlayer` → 改 → `savePlayer`。响应里注明走的哪条路。
  - 所有输入做数值/存在性校验，未知 op 拒绝。
- `server/editor/`（新，纯 vanilla HTML/CSS/JS，无构建步骤）：深色游戏风主题（深蓝黑底 + 青紫渐变强调色、卡片圆角、毛玻璃侧栏），全中文。

### 前端功能（简单易上手）
- 左侧栏：服务器状态 + 账号列表（点选切换）。
- 右侧标签页：
  1. **总览**：昵称、等级/经验编辑、货币（9001-9008）数值直接改；
  2. **背包**：分类筛选 + 搜索；改数量 / 删除 / 添加道具（目录搜索弹窗）；一键资源礼包按钮；
  3. **角色**：角色卡片网格（含未拥有角色灰卡）；「一键添加全部角色」；单人详情：等级/经验/突破次数、装备武器等级/突破/精炼编辑、「发放专武」按钮；
  4. **抽卡**：各池保底计数（no_up_times）编辑；
  5. **商城**：累充积分、月卡有效期编辑；
  6. **剧情**：只读展示主线进度（不提供写入，避免破坏任务状态机）；
  7. **备份**：一键导出（默认位置或自定义路径）+ 快照列表展示。
- 顶部保存按钮 + toast 提示（「已在线生效」/「已写入，重登后生效」）。
